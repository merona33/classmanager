# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

**담임의 노트 (Homeroom Teacher's Notes)** — a Korean classroom management PWA for Mac. This directory holds only the **pre-built distribution**, not source code. There is no build step, no package.json, no test suite, no linter. It is a git repository (remote `merona33/classmanager`); pushing `main` deploys `app/` to GitHub Pages via `.github/workflows/pages.yml`.

Besides `app/`, the root contains `firestore.rules` (security rules to paste into the Firebase console), `.github/workflows/pages.yml` (deploys only `app/` to GitHub Pages), `.gitignore` (keeps `*.xlsx`, which may hold real student names, out of git), `사용법.txt` (end-user Korean install/usage guide, including the `.command` launcher flow and troubleshooting) and `7반_명렬표.xlsx` (sample class roster for the Excel upload feature).

## Running the app

```bash
python3 -m http.server 8765 --directory app
```

Then open `http://localhost:8765`. A service worker requires `http://localhost` or HTTPS, so opening `index.html` via `file://` will not work. The end-user launcher `담임의노트_실행.command` (referenced in `사용법.txt`, not present in this directory) does the same thing and auto-increments the port (8766, 8767, …) if 8765 is busy.

## App structure

```
app/
  index.html              # Entry; loads config.js + sync.js (classic scripts), then the module bundle; registers sw.js
  config.js               # Firebase apiKey + projectId (empty = sync disabled, plain localStorage)
  sync.js                 # Optional multi-computer sync: login overlay, pull on start, debounced push, status badge
  notify.js               # Optional schedule reminders (window.cmNotify), browser notifications while the app is open
  sw.js                   # Service worker (cache name `classmanager-v30`; also focuses the app on notification click)
  manifest.webmanifest    # PWA manifest (lang ko, standalone)
  icon*.png, apple-touch-icon.png
  assets/
    index-<hash>.js       # Single minified React bundle (~690 KB, includes the SheetJS xlsx library)
    index-<hash>.css
```

## Key architectural facts

- **Grades screen** (`성적 관리`, component `FO` in the bundle): per period and subject it stores `{score, std, percentile, grade}` under `grades:<classId>` → `{mock|internal}[studentId][period][subject]`. Printing the grade report goes through `CmPrint("landscape"|"portrait")` (buttons `가로 인쇄`, `세로 인쇄`, `전체 가로 PDF`, `전체 세로 PDF`), which injects a temporary `<style>` with a top-level `@page { size: A4 <orientation>; margin: 10mm }` plus compact `.cm-report` layout rules (`@media print`) just before `window.print()` and removes it on `afterprint`. Landscape = one page per student (mock and internal cards side by side); portrait = two pages per student (header+summary+mock, then internal; cards use `break-inside: avoid`). The `@page` rule inside the bundle's own `@media print` block is not honored by Chrome, which is why the orientation is injected at top level. Internal (내신) grades have only two periods, `1학기` and `2학기` (`Eu`); on first load `grades:<classId>.periodsV` is set to 2 and old `1학기/2학기 1차·2차` entries are copied into the semester key (latest exam wins, originals kept untouched). `나이스 가져오기` (internal tab only: `CmNeisParse` → `CmNeisMatch` → `CmNeisImport` dialog → `cmNeisApply`) reads a NEIS 학기말 성적 종합일람표 sheet: it finds the header row by the cells `번호/성명/교과목`, then each student block by the label `합계(원점수)` and the following label rows `성취도`, `석차등급`, `석차`, `수강자수`; values are matched to subject columns by header text, students by 번호 (falling back to a unique 성명 match when names differ), and stored per subject as `{score, ach, grade, rank, n}` merged over existing values (blank student blocks are ignored). Real NEIS exports format cells like `87.02(87)` (원점수, rounded value in parentheses), `46(2)` (석차, tie count) and `()` (empty), so numeric parsing takes the leading number and treats the rest as noise. The header line `2026학년도 1학기 주간 1학년 7반 …` is read to preselect the semester and to warn when the selected class differs from the file's 반. Names may be masked (`홍*동`; `*` is a wildcard when matching). The dialog shows skipped students with masked names only; the file is read locally by SheetJS, never uploaded, and names are not persisted (only scores are saved). NEIS subject names are cleaned (`공통국어1(3)` → `국어`) and editable in the dialog. Subject lists are editable per class and per type (`과목 편집` → `CmSubjEdit`): the custom list is stored as `grades:<classId>.subjects.{mock|internal}` (absent = defaults `yu`/`ku`); renaming a subject migrates stored scores to the new key, deleting only hides them (re-adding the same name restores them). The summary object carries `subjectNames` so `ap`/`ip`/`CmGrowth` render the same list. Input columns and the template are ordered 원점수, 표준점수, 백분위, 등급. **Multi-year grades (2·3학년 classes only)**: the input toolbar gets a 학년 picker (1학년 … current grade, `cmYr`) and stored period keys are prefixed, e.g. `"1학년 3월"`, `"2학년 1학기"` (`A` = full key, `cmPF(type)` = all keys for the summary); grade-1 classes keep bare keys (`"3월"`). On first load a 2/3학년 class with `yearV !== 1` copies bare keys to `"<grade>학년 <period>"` (originals kept) and sets `yearV: 1`. The summary carries `periods` and `years`; `ap` then shows `CmYearSum` (학년별 종합: mock average and 내신 per semester/year, plus 전 학년 누적) inside the profile card, `CmIpYears` (one `ip` table per 학년, only periods/subjects with data), and `CmGrowth` compresses to periods with data and draws 학년 labels/dividers. In the NEIS dialog the semester list covers every year; picking a previous-year semester (or a file whose 학년 is lower) switches matching to name-only (`CmNeisMatch(fs, ss, true)`) because 반·번호 differ between years, and does not raise the wrong-class warning. The 학생별 요약 view (component `ap`) also renders `CmGrowth`, a hand-written SVG trend chart (per subject plus 평균, switchable between 등급/백분위/표준점수/원점수, grade axis inverted) under each of the mock and internal tables; note the compiled CSS only contains Tailwind classes the original source used, so new UI must use inline styles for any spacing/utility not already in `index-*.css`. Excel upload maps columns by header text (`<과목>_원점수` etc.), so old 3-column templates still import; a column absent from the file leaves existing values untouched.
- **Seating screen** (`SO`, desk generator `np`): `seating:<classId>` holds `{shape, rows, cols, teacherPos, boardPos, desks[], layoutV}`. Desk coordinates are percentages of the canvas and are generated by `np`; desks span roughly y 19%→81% so there is room for 교탁/칠판 above *or* below. Saved layouts without `layoutV: 3` are regenerated by `np` on load (students and pins carried over by index). Shapes are `grid`, `u` and `round` (shown as **조별**): for `round`, `rows` = number of 조 (1–12) and `cols` = desks per 조 (1–8); each 조 is a tight cluster (2 columns, or ceil(n/2) columns for n>2) with a `group` number on its desks, drawn with a dashed box and an `N조` label (`CmGroups`, also used by the print popup). Random placement with 남녀 balance deals boys and girls round-robin across 조. **Each shape keeps its own layout**: switching shape (`d` in `SO`) stashes the current `{rows, cols, teacherPos, boardPos, desks}` under `layouts[<old shape>]` and restores `layouts[<new shape>]` if present; only a first visit to a shape builds desks with `np` (carrying students over by index; grid/ㄷ자 then reuse a saved grid/ㄷ자 size instead of the 조 수). The top-level fields always hold the active shape, so data saved before `layouts` existed loads unchanged. It is all one `seating:<classId>` value, so sync needs no change.
- **Mobile layout** (`index.html` `<style>`, `@media screen and (max-width: 768px)` only): the shell carries hook classes added to the bundle (`cm-shell`, `cm-side`, `cm-brand`, `cm-classpick`, `cm-nav`, `cm-sidefoot`, `cm-main`). On phones the sidebar becomes a one-line title plus a horizontally scrolling 반 picker, the `nav` becomes a fixed bottom tab bar (z-index 40, below the z-50 modals), and `grid-cols-12` two-column screens stack. The bundle CSS link comes *after* that `<style>`, so these rules use a `.cm-shell` prefix to win on specificity. Desktop and print are unaffected.
- **Schedule & notices screen** (`일정·공지`, tab id `schedule`, component `CmSched` plus `CmNotifyPanel`, appended to the bundle just before `ac.createRoot`): `schedule:<classId>` holds `{events:[{id,date,time,title,content,remind}], notices:[{id,date,title,content,pinned}]}` (dates are local `YYYY-MM-DD` via `cmYmd`, not `toISOString`). Upcoming events are sorted ascending with D-day labels, past ones are collapsed; notices are pinned-first then newest. Excel download/upload uses columns 구분/날짜/시간/제목/내용/알림·고정 and upload appends with de-duplication. The 알림 on/off switch is device-local (`cm-notify` = `{on, daily:"08:00", lead:30}`, sent log `cm-notify-sent`) and handled by `notify.js`: it scans every `schedule:*` key every 30 s and on focus, sends one 오늘 일정 summary after the daily time and one reminder `lead` minutes before each timed event (`remind:false` events are skipped, already-past ones are never sent late). There is no push server, so notifications only fire while the app is open (iPhone: only from a home-screen install).
- **Design**: neutral white/gray surfaces with a single blue accent (`--accent: #2563EB`, defined in the `cm-style` block injected by `_O` plus overrides in `index.html`); sans-serif only (Noto Sans KR), no paper texture. Keep new UI to the existing CSS variables.
- **Grade + class selection**: the sidebar has a 학년 (1–3) segmented control and a 반 (1–15) grid. The class id used in every storage key is `cmCid(grade, cls)`: **grade 1 keeps the bare number (`students:7`) so pre-existing data is untouched**, grades 2/3 use `"2-7"` (`students:2-7`). `cmCparse`/`cmCL` (`2학년 7반`)/`cmCF` (file names) convert; `app:meta.lastClass` holds the id. `notify.js` formats both id styles. The NEIS import warns if the file's 학년/반 differ from the selected class.
- **Attendance screen** (`출석부`, tab id `attend`, component `CmAttend`, appended before `ac.createRoot`): `attendance:<classId>` = `{days:{"YYYY-MM-DD":{done, marks:{studentId:{t:"absent"|"late"|"early"|"result", r:사유, m:메모}}}}}`; default is 출석 (only exceptions stored), every tap saves immediately, and the key is in `sync.js` PREFIXES so it syncs like the others. Date picker with prev/next, 모두 출석, daily counts, monthly totals; Excel download (one column per recorded date, cells like `결석(질병): 메모`) / upload with the same format.
- **Six screens**, defined by a tab list in the bundle (now seven with 출석부): 학급 관리 (class), 출석부 (attend), 자리 배치 (seating), 성적 관리 (grades), 마음 관계 (relations), 상담 내역 (counsel), 일정·공지 (schedule). Each has Excel download/upload buttons, which are the only backup/transfer mechanism between computers or browsers.
- **Persistence is `localStorage` only**, accessed through a small async wrapper (`Et.get/set/del`, JSON-serialized, errors swallowed). Keys are namespaced per class id: `app:meta` (class list and metadata), `students:<classId>`, `seating:<classId>`, `grades:<classId>`, `relations:<classId>`, `counsel:<classId>`, `schedule:<classId>`; UI preferences live in `cm-fonts`, `cm-style` and `cm-notify`. Without sync, data is per browser and per origin (Chrome vs. Safari, or a different port, sees separate data); with sync enabled see below.
- **Multi-computer sync (optional)**: when `config.js` has a Firebase `apiKey` and `projectId`, `sync.js` shows an email/password login screen and mirrors the `students:/seating:/grades:/relations:/counsel:/schedule:/attendance:` keys to Firestore documents `users/{uid}/kv/{key with ':' → '~'}` (fields `value` = the raw JSON string, `updatedAt` = ms). It talks to the Identity Toolkit, securetoken and Firestore REST APIs with plain `fetch` (no SDK); endpoints can be overridden in `config.js` (`identityUrl`, `tokenUrl`, `firestoreUrl`) to point at a mock for testing. `Et.get` in the bundle awaits `window.cmSync.ready`; `Et.set/del` call `cmSync.touch/remove`. `localStorage` stays the working copy; unsent keys are tracked in `cmsync:meta.dirty` and retried (offline-safe). Conflicts are last-write-wins per key. `app:meta` and `cm-*` stay device-local. Remote changes seen while the app is open only raise a "reload" banner (not applied live, because the React state would be stale). Logout wipes the synced keys from that browser.
- **Offline behavior**: `sw.js` precaches only the `CORE` list (`./`, `index.html`, manifest, `config.js`, `sync.js`, `notify.js`, two icons) at install. Hashed files under `assets/` are cached lazily on first successful same-origin GET (cache-first, falling back to cached `index.html` on network failure). Cross-origin requests (the Firebase APIs) bypass the service worker.

## Modifying the app

The original source is not available, so changes are made by editing the minified bundle in `app/assets/` directly. Use targeted greps (for example for a Korean UI label or a storage key) rather than reading the file, since it is a few very long lines.

If you edit or rename any file the browser may already have cached, bump the `CACHE` string in `app/sw.js`. Because fetch is cache-first and `index.html` is precached, clients will otherwise keep serving stale files. If you rename the hashed bundle files, also update the references in `index.html`.
